# Eden Clinic OS — M7 Runtime Hardening Design Record

**Status:** approved with five implementation-plan amendments  
**Scope:** M7 only — PWA installability, static-shell offline recovery, strict CSP delivery, deferred dependency-audit remediation, and three accepted M6 polish items. M7 is the final v1 milestone.

## 1. Purpose, authority, and scope fence

M7 makes the accepted static export durable across a browser restart and deployable with a strict security policy. It implements the M0–M6 handoff: a hand-written service worker, manifest, correct RSC `.txt` MIME handling, strict CSP, and an actual reboot-recovery acceptance test. It retains the self-hosted fonts, static export, data-layer/outbox/session boundaries, token checksum, typed i18n, and five-gate workflow.

This record is governed by `docs/eden-frontend-build-spec-v1.1.md` (v1.2 content), the M3/M4/M6 accepted security handoffs, `docs/reference/demo-v4.html`, the pilot-blocker register, and the M6 acceptance ruling. No API contract, outbox kind, clinic mutation, capture arithmetic, session-envelope policy, or product workflow changes in M7.

The browser remains the cache for the static shell only. Dexie remains the source of offline business data; the existing outbox remains the only capture-sync mechanism. A service worker must never cache API responses, fake connectivity, or make a queued sale appear drained.

## 2. File ownership and build artifact

| Area | Files | Responsibility |
|---|---|---|
| PWA source | `public/sw.js`, `public/manifest.webmanifest`, `public/icons/eden-192.png`, `public/icons/eden-512.png` | Hand-written worker source, install metadata, and self-owned Android-installable icons. |
| Build security | `scripts/build-pwa.mjs`, `scripts/generate-csp.mjs` | Stamp the exported worker version/precache list, hash each exported HTML route, and emit CSP deployment artifacts. |
| Runtime registration | `src/app/providers.tsx`, `src/ui/Toast.tsx`, `modules/sale/*` | Post-mount registration and user-consented update activation; the existing in-memory Sale cart guard also protects restart; no module-scope browser access. |
| Test host | `tests/e2e/static-server.mjs` | Serve static output, `text/x-component` RSC payloads, and generated CSP headers exactly as a host must. |
| Evidence | `tests/e2e/m7.export.spec.ts`, `tests/e2e/visuals.ts` | Strict-CSP, manifest, update, and true reboot-recovery coverage using renderer-owned test IDs only. |
| Polish | `print/receipt.ts`, `modules/today/*` | Prominent raster COPY marker and red negative drawer difference. |
| Supply chain | `package.json`, `package-lock.json`, `.github/workflows/ci.yml` | Exact transitive overrides, deterministic lockfile update, and audit gate. |

`npm run build` becomes an atomic artifact pipeline: Next first writes `out/`; the M7 post-build step hashes sorted precache paths plus the bytes of each matching file, stamps that content-derived service-worker version and route URLs, writes CSP artifacts from those exact generated bytes, and validates the manifest assets. A failed post-build step fails the build; it may not leave a partial `out/` artifact. An identical artifact produces the same version; changing even one precached HTML/RSC/static byte produces a different version.

## 3. PWA shell and update contract

### 3.1 Install metadata

`manifest.webmanifest` declares a stable root `id`, Eden Clinic OS, a short Eden label, root scope, `/login` start URL, `standalone` display, `prefer_related_applications: false`, and the existing cream/cobalt token values for splash/theme presentation. It names two self-owned PNG icons at 192×192 and 512×512 as separate `any` and `maskable` entries. They are generated/reviewed local assets; no icon, logo, font, or install resource is fetched from a CDN.

The root layout links the manifest and updates the stale M1 metadata. Android Chrome installability is checked against the exported static build on a secure production origin (or localhost in test); M7 does not add a bespoke in-app install prompt.

### 3.2 Hand-written worker and cache boundaries

`public/sw.js` remains a small hand-written worker. The post-build step replaces only explicit version/precache placeholders in its exported copy, producing an immutable shell cache name from a digest of sorted precache paths and their file bytes (not merely the URL list). Its precache URL list contains every static route shell, RSC `.txt` payload, hashed Next asset, local font, manifest, and icon required by the export. Route URLs are emitted in the extensionless form that the static host receives (`/login`, not an implementation-only filesystem name).

On install, the new worker fills its new cache with `new Request(url, { cache: 'reload' })` entries, so precache bypasses the browser HTTP cache and receives the host's current bytes; it does not activate over an existing controller. On activation after consent, it removes older Eden shell caches. For same-origin exported shell/static requests it uses cache-first and serves only the precomputed cache entries; it does not dynamically cache requests outside that list. `cache.match(request)` intentionally keeps query strings significant: a future query-bearing navigation falls through to network and then the offline login fallback, rather than accidentally receiving a shell for a different query. A same-origin **navigation** cache miss first attempts the network; if that fails, it deterministically returns the precached `/login` shell. Thus a deep, mistyped, or unexported URL during an outage lands at the correct memory-session boundary instead of a browser error page. `/api/*`, should a future deployment place it on the app origin, is network-only pass-through. The separately hosted build-injected API origin is not intercepted at all. No API response, bootstrap, delta, outbox request, receipt PNG Blob, or IndexedDB value enters a Cache Storage cache.

The worker never calls `skipWaiting()` by itself and never calls `clients.claim()`: a first install must not take over or reload an in-progress page. The app registers it only in a post-mount client effect, detects a waiting update, and displays one translated manual-dismiss toast with a translated **Restart** action. The action consults the same structurally separate, in-memory `hasUncommittedCart` predicate already used by A4 Switch user; it never examines outbox depth or sync state. While a cart has lines or tender is open, Restart is disabled with translated finish-or-abandon copy and must not post `skip-waiting`. Once the cart is committed, cleared, or the tender flow closes, Restart re-enables. Selecting an enabled action arms one `controllerchange` listener immediately before posting `skip-waiting`; that one-shot listener alone reloads into the new static artifact. No listener exists at mount, so first install and an update accepted in another tab cannot reload this tab mid-flow. M7 deliberately has no persistent re-entry for a dismissed update toast; the worker discovers it again on the next full load. A durable Set-up diagnostics row is deferred rather than added as an unreviewed counter control.

The deployed static server must continue resolving extensionless requests to the matching `.html` export and returning exported Next RSC `.txt` payloads as `text/x-component`. It must serve route HTML, RSC `.txt`, `sw.js`, and the manifest with `Cache-Control: no-cache` so a CDN revalidates the current artifact before ordinary navigation or worker precache. Hashed `/_next/static/**` assets must instead be immutable (`public, max-age=31536000, immutable`). These host rules and the CSP map travel together in the M7 deployment handoff. The worker caches and returns the original `Response`, including its MIME type and security headers. Serving `.txt` as `application/octet-stream` remains a deployment defect because it breaks soft navigation and loses the memory-only session.

## 4. Strict CSP is a generated deployment artifact

### 4.1 Policy shape

Static export cannot mint a per-response nonce, and `'unsafe-inline'` would defeat the security goal. After Next emits `out/`, `generate-csp.mjs` hashes the exact contents of every inline `<script>` (and, if present, inline `<style>`) in each exported HTML document with SHA-256. The generator emits a policy with the document's exact hash set and no `'unsafe-inline'` or `'unsafe-eval'`:

```text
default-src 'self'; base-uri 'self'; object-src 'none'; frame-ancestors 'none';
form-action 'self'; script-src 'self' 'sha256-…'; style-src 'self' 'sha256-…';
img-src 'self' blob:; font-src 'self'; manifest-src 'self'; worker-src 'self';
connect-src 'self' <build API origin>
```

The final serialization may omit an empty hash list but may not broaden a directive. Inline style *attributes* are not hashable in this model and must be removed before M7; the current `Skeleton` style-property API is converted to CSS-class/data-attribute sizing. A static style block is allowed only when its actual hash is present. This keeps app markup, renderer output, and the CSP consistent rather than silently relying on a style exception.

Next's generated default 404 document contains framework-owned inline style attributes, so M7 supplies an app-owned, tokenized and translated `not-found` route. This is enforced by the post-build generator: `_not-found.html` and `404.html` must satisfy the same no-inline-style rule as every operational route; the strict policy is never weakened merely to accommodate a framework fallback.

`connect-src` is derived from the validated `NEXT_PUBLIC_EDEN_API_BASE_URL` supplied to that build, never hard-coded. A production receipt drill may later add the exact HTTPS LAN ePOS endpoint required by a printer transport; that is a deliberate CSP amendment at the hardware drill, not a pre-authorized wildcard. The development/test policy contains its loopback mock origin because it is derived from that build environment.

### 4.2 Per-route map, portable union, and atomic deployment

The generator writes both of these output-only deployment artifacts:

- a preferred per-route header map, keyed by exported HTML route; and
- a portable union header containing the de-duplicated SHA-256 set across every route.

The union is not materially weaker: each member authorizes only its exact script bytes, wherever those bytes appear. It lets a host with one global-header capability enforce CSP without edge functions, while Netlify/Cloudflare-style hosts may use the smaller route-specific map.

Hashes necessarily change when the export changes. The selected header map (or union) is therefore deployed atomically with the matching `out/` directory; a stale policy does not merely weaken the app, it blocks its inline RSC bootstrap. The static-server test host reads the generated per-route map and applies it as an HTTP `Content-Security-Policy` response header. Production hosting receives both generated forms as part of the same immutable deployment unit; host choice remains open until 7 August without reopening M7.

This is self-consistent with the service worker: Cache Storage retains the response headers that arrived with each cached shell. An old cached shell therefore remains paired with its own old hashes until the user accepts the new worker; it cannot be served under a new, incompatible CSP map.

M7 deliberately supersedes the pilot blocker register §1 sketch of shell `stale-while-revalidate`. Cache-first, versioned shell caches, and a user-consented atomic swap remove its mixed-version window. At M7 acceptance the owner-maintained register §1 is updated to state this replacement, so the evidence ledger and the implemented policy do not contradict one another.

## 5. Reboot recovery and CSP acceptance

The M7 export E2E uses a real persistent Chromium profile, not a same-page simulation:

1. online, provision/login, wait for worker installation, and reload once online so the worker controls the page;
2. enter the actual offline state with `context.setOffline(true)`, capture sales, and verify non-done outbox depth;
3. close the persistent browser context to model a power cut;
4. launch a new persistent context using the same profile with `offline: true` in the `launchPersistentContext()` options — before any page is created or navigation starts — navigate to `/login`, and prove the worker serves the shell, staff picker, local envelopes, and queued rows;
5. PIN-unlock, verify the queued sales remain unchanged, restore connectivity, and prove one drain reaches the mock with the original rows; and
6. inspect the offline navigation response: the generated CSP is still present, RSC navigation keeps `text/x-component`, the explicit offline navigation cache-miss returns the login shell, and no `securitypolicyviolation` event occurs.

This is the first milestone where `context.setOffline(true)` is valid for static assets: the app shell has already been installed and is controlled by the worker. It does not replace the existing API-abort tests for narrowly simulating API failure.

Every export-project selector is a renderer-owned `data-testid`; no test selects a translated label or visible string. A spec may reload only when the assertion intentionally concerns reload/reboot behavior; it never `page.goto()`s an authenticated product route mid-flow. Toasts are manual-dismiss, so a test dismisses a blocking toast before interacting with underlying controls.

The CSP suite also proves enforcement, rather than merely observing a header string:

- each exported route receives the generated header and loads with zero `securitypolicyviolation` events, including a ReceiptViewer reprint so `blob:` receipt image use is exercised;
- the test-only `__csp-tripwire` response carries the generated union policy plus one explicit hash for an evaluation probe; its deliberately **unhashed** inline script is blocked and produces a violation;
- the hashed probe attempts `eval()` and is blocked, proving the policy excludes `'unsafe-eval'`; the zero-violation application-route sweep proves the delivered runtime does not require it; and
- the offline SW-controlled reopen repeats the header/no-violation assertion, not merely the first network load.

The tripwire exists only in `static-server.mjs` under the established `__` test-host convention. It is not an OpenAPI endpoint and is absent from production assets.

## 6. Deferred supply-chain findings

The M2-deferred audit reports three high findings through `next@16.2.12`: its exact `postcss@8.4.31` and optional `sharp@0.34.5` trees. Registry resolution on 3 August confirms the compatible fixed versions `postcss@8.5.25` and `sharp@0.35.3`; Next's optional Sharp range accepts the latter. The direct Next pin stays `16.2.12` because it is the real latest stable 16.x line and the audit lists no independent Next fix.

M7 adds exact npm `overrides` for those two transitive packages, regenerates the committed lockfile deterministically, and installs no new runtime dependency. CI adds `npm audit --omit=dev --audit-level=high` after `npm ci`; M7 is not complete while it reports a high or critical production vulnerability. `npm audit fix` remains prohibited because it can make an unreviewed range decision.

## 7. Accepted M6 polish

The reprint marker remains inside the one receipt raster renderer but gets a distinct `copy-marker` metric: larger, bold, centred, and visually separated from ordinary receipt runs at both 576 and 384 dots. It uses the confirmed selected header/body font policy and remains translated; original receipts remain marker-free. The August 8-9 physical-printer drill checklist must confirm COPY-marker contrast after the thermal printer's raster conversion; if it is weak, change only the marker glyph to ink-black as a display-only follow-up.

The shift-close difference value uses the semantic red token when `countedCash - expectedCash < 0`; zero and positive values retain ink. The existing integer-MMK calculation remains exclusively in `money.ts`; this is display treatment, not a second arithmetic path.

Evidence helpers accept a target locator and call `scrollIntoViewIfNeeded()` before each targeted capture. M7 updates the M6-style captures so the Set-up diagnostics card, not an above-fold region, is visible in its own evidence image.

## 8. Verification, visual evidence, and exclusions

Unit coverage verifies CSP extraction/hash canonicalization, per-route/union generation, API-origin derivation, rejection of inline style attributes, worker precache route mapping, manual update consent, cache-version cleanup, the larger COPY run, and negative-only red drawer treatment. The build test verifies the final exported worker, manifest, icons, route map, and union header exist as one artifact. Existing five gates remain intact; the export and dev-locale Playwright projects still run together.

The M7 evidence set includes a controlled offline reboot at 1280×800, worker update-ready/restart state, CSP tripwire result, manifest/installability inspection, a 576-dot COPY reprint, a negative-difference close modal, and a scrolled Set-up diagnostics capture. Owner visual review remains authoritative.

M7 does **not** add background sync, API caching, a fallback password verifier, persisted elevation, an idle-lock decision, a real LAN/Bluetooth printer transport, a printer `connect-src` wildcard, new analytics/hub/flags, a backend route, or a service-worker-owned data model. The explicit printer-host CSP amendment remains for the physical hardware drill.
